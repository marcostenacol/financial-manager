# Regras obrigatórias

1. **Nunca** colocar lógica de negócio ou chamada ao Prisma (`prisma.{model}.*`) no Controller — pertence ao Service/Repository.
2. **Nunca** retornar `reply.send()`/`reply.status().send()` direto num Controller de domínio — usar `this.success(reply, ...)`/`this.error(reply, ...)` (herdados de `BaseController`).
3. **Sempre** validar entrada com o schema Zod correspondente (`{DTO}.parse(request.body)`) ao escrever um método de Controller novo — não introduza `request.body as any` em código novo, mesmo que seja o padrão presente em parte do código existente (ver `CLAUDE.md` > Débito Técnico #8).
4. **Sempre** usar `AppError` para erro de negócio esperado (`throw new AppError('mensagem', status_code)`), nunca `throw new Error()` solto quando o erro precisa virar uma resposta HTTP controlada.
5. **Nunca** usar valor literal para representar conceito de domínio fechado (status, tipo, papel) sem checar se já existe um Enum (`TransactionStatusEnum`, `TransactionTypeEnum`, `WalletTypeEnum`, `RoleEnum`) — se o domínio for fechado e não houver Enum, crie um em `enums/` dentro do módulo antes de usar a string/número solto.
6. **Nunca** usar status HTTP como número mágico sem necessidade — quando fizer sentido, prefira nomear (`201`, `404` já aparecem como literais no código real hoje; não há import de constantes de status como no projeto de referência GIZ porque não há uma lib equivalente ao Symfony `Response` aqui — apenas mantenha o número alinhado ao que `this.success`/`this.error`/`AppError` já usam de fato, sem inventar código HTTP fora do padrão REST comum).
7. **Toda dependência (Repository, Service, `CacheTrait`) entra pelo construtor** via `@inject()`/`tsyringe`, e precisa estar registrada em `src/shared/container/index.ts` — nunca `new {Service}()`/`new {Repository}()` direto fora de teste.
8. **Nunca** interpolar valor em SQL cru. Se usar `prisma.$queryRaw`, sempre via tag template com placeholder (`` prisma.$queryRaw`WHERE id = ${id}::uuid` ``), nunca concatenação de string.
9. **Sempre** declarar tipo de retorno explícito em método público de Service/Repository/Controller — `strict: true` já está ativo no `tsconfig.json`; não regrida isso com `any` implícito em código novo (casts explícitos como `as any` em código legado são um débito conhecido, não uma licença para introduzir mais).
10. **Sempre** invalidar o(s) cache(s) relevantes (`cache.del(...)`) dentro do próprio Service que fez a escrita, imediatamente após a operação de escrita — é o padrão real observado (`CreateTransactionService` invalida `transactions:wallet:{id}`, `transactions:user:{id}` e, se afetar saldo, também `wallet:detail:{id}`/`wallets:user:{id}`).
11. **Nunca** acessar propriedade de um resultado potencialmente `null` do Prisma (`findUnique`/`findById`) sem checar antes — usar guard clause com `AppError` (`if (!wallet) throw new AppError(...)`), como já é feito em `CreateTransactionService`.
12. **Sempre** checar posse do recurso (`registro.userId !== userId`) no Service antes de operar sobre um recurso identificado por `:id` de rota — nunca confiar que o `id` da URL já pertence ao usuário autenticado.
13. **Importações**: todas via `import ... from '...'` no topo do arquivo — nunca `require()` (o projeto é `"type": "commonjs"` no `package.json` da API, mas o código real usa sintaxe ESM de `import`/`export` compilada pelo TypeScript; siga o padrão real, não a flag do `package.json`).
14. **Preservação de Código**: não altere código existente sem solicitação explícita — mesmo quando ele reproduz um dos pontos de débito técnico listados no `CLAUDE.md`. Sinalize, não corrija de passagem.
15. **UI**: toda chamada HTTP via a instância `api` de `src/services/api.ts` — nunca `fetch()` nem um novo `axios.create()` num componente/página.
16. **Nunca** commitar valor real de `.env` (credenciais de banco, `JWT_SECRET`, etc.) em código, migration, seed ou documentação — usar `.env.example` como referência de nome de variável.
